# 06_mobile_and_local_first_storage

## 【モバイル & Local-Firstストレージ設計】WorldCraft 堅牢化仕様
### 1. モバイル環境（iOS / Android）特有のファイルI/O制約と障害対策
iPad＋外付けキーボードやスマートフォンでの推敲・設定確認において、モバイルOSネイティブ環境で発生しやすいファイル破損や書き込み中断を防止します。
| OS / 環境 | 発生しやすい制約・障害モード | システム・UXへの影響 | WorldCraftの防御的設計 |
| --- | --- | --- | --- |
| iOS / iPadOS (APFS) | rename による置換失敗 | 上書きrenameが例外（EEXIST等）を吐き、一時ファイルが残存 | 明示的削除を挟む安全な置換フォールバック |
| iOS (iCloud Drive) | ファイル未実体化 (Faulted) | クラウド上にのみ実体がありI/Oがハングする | 存在確認と同期状態の事前ヘルスチェック |
| 共通 (モバイル全般) | サスペンド時の書き込み中断 | アプリ切り替え時にプロセスが即座に停止しデータが0バイト化 | pagehide / pause イベント時の即時同期フラッシュ |
| Android (SAF) | ファイル監視イベントの遅延 | ストレージ監視イベントの欠落により状態不整合 | インメモリ状態とストレージのタイムスタンプ検証 |

### 2. モバイルセーフなアトミック書き込み（safeAtomicWrite）
データ破損による信用失墜をゼロにするため、多段バリデーション付きアトミック保存を標準化しています。
- 一時ファイル書き込み: .worldcraft_data.tmp へ書き込み。
- 完全性検査（サイズとパース確認）:
  - 書き込み後のファイルサイズが0バイトでないことを検証。
  - JSON形式の構文解析テストを実行し、破損データのコミットを遮断。
- OS別置換フォールバック:
  - デスクトップ: 標準アトミック置換。
  - モバイル: 宛先ファイルの存在確認・事前削除を経てrenameを実行。
- ロールバック処理: 例外発生時は一時ファイルをクリーンアップし、前回の正常セーブデータを維持。
### 3. サスペンド耐性とライフサイクル監視
- ユーザーがブラウザタブを閉じた、またはアプリをバックグラウンドに回した瞬間に、保留中のデバウンスキューを強制消化するハンドラーを登録：
  - window.addEventListener('pagehide', ...)
  - window.addEventListener('beforeunload', ...)
  - document.addEventListener('pause', ...) (Cordova/Capacitor互換)
- デバウンス時間の動的調整:
  - デスクトップ環境: 300ms（キビキビした即時保存）
  - モバイル環境: 800〜1,200ms（バッテリー消費と端末発熱を抑止しつつ、一息ついたタイミングで安全にI/O実行）
### 4. Local-First & Obsidian Vault 互換性
- データ主権の死守: 全設定データはローカルブラウザ（IndexedDB / LocalStorage）およびローカルファイルシステムに保持。
- Obsidian双方向連携:
  - 設定データおよび小説原稿は、Obsidian Vault互換のMarkdown + YAML Frontmatterとしていつでもエクスポート可能。
  - ウィキリンク記法（[[...]]）の互換性を完全維持。
